# Память для Claude Code - хватит объяснять заново

## Зачем это нужно
Каждая новая сессия в консольных ИИ-инструментах по умолчанию начинается с чистого листа. Разработчикам приходится заново объяснять архитектуру проекта, используемый стек технологий, правила именования переменных и команды запуска сборки. Это приводит к бессмысленной трате времени и токенов. Использование встроенной системы памяти Claude Code (файла конфигурации `CLAUDE.md` и механизма авто-памяти) полностью решает эту проблему. ИИ-ассистент мгновенно считывает инструкции проекта при старте и самостоятельно запоминает важные технические решения по ходу работы. Данный гайд научит вас правильно организовывать память Claude Code для бесшовной разработки.

## Что внутри
* Понимание работы двухуровневой системы памяти: файл `CLAUDE.md` и автоматическая память.
* Инструкция по созданию и структурированию файла `CLAUDE.md` в корне репозитория.
* Команды управления авто-памятью и работа с консольным интерфейсом `/memory`.
* Рекомендации по составлению эффективных правил сборки, стиля и тестирования.
* Практические примеры файлов памяти для фронтенд и бэкенд проектов.
* Разбор частых ошибок при настройке памяти и способов очистки устаревшего контекста.

## Пошаговая инструкция

### Шаг 1. Установка и первичное окружение Claude Code
Перед настройкой памяти убедитесь, что у вас установлена актуальная версия консольного ассистента.

1. **Установка в Windows через PowerShell:**
   Выполните следующую команду в консоли PowerShell:
   `irm https://claude.ai/install.ps1 | iex`

2. **Альтернативная установка через менеджер пакетов npm (требуется Node.js 22+):**
   `npm install -g @anthropic-ai/claude-code`

3. **Проверка корректности установки:**
   `claude --version`

### Шаг 2. Создание главного файла инструкций CLAUDE.md
Файл `CLAUDE.md` размещается в корневой директории вашего проекта. Он автоматически считывается Claude Code в момент запуска диалоговой сессии.

1. Создайте в корне проекта файл с именем `CLAUDE.md`.
2. Заполните его структурированными инструкциями по следующему шаблону:

```markdown
# Конструкция и правила проекта N

## Команды сборки и тестирования
- Запуск проекта в режиме разработки: `npm run dev`
- Сборка продакшн бандла: `npm run build`
- Запуск модульных тестов: `npm run test`
- Проверка линтером: `npm run lint`

## Стиль кода и архитектура
- Используем TypeScript со строгой типизацией (strict: true).
- Компоненты верстаем по БЭМ в отдельной папке components/.
- Все асинхронные вызовы обрабатываем через try/catch с логированием.
- Форматирование кода через Prettier (двойные кавычки, точка с запятой).
```

### Шаг 3. Использование механизма Авто-памяти (Auto-memory)
В процессе работы Claude Code самостоятельно фиксирует важные технические особенности вашего проекта (например, архитектурные нюансы или найденные спецификации базы данных) во внутреннем хранилище авто-памяти.

1. **Просмотр накопленной памяти:**
   Введите встроенную команду в терминале Claude Code для просмотра всех сохраненных заметок:
   `/memory`

2. **Редактирование авто-памяти:**
   Команда `/memory` открывает интерфейс просмотра и редактирования автоматически созданных правил. Вы можете удалить устаревшие факты или откорректировать ошибочно запомненные детали.

### Шаг 4. Иерархия файлов памяти в крупных проектах
Если у вас крупный монорепозиторий или проект с несколькими изолированными модулями, вы можете создавать дочерние файлы `CLAUDE.md` внутри поддиректорий (например, `src/frontend/CLAUDE.md` и `src/backend/CLAUDE.md`). Claude Code будет считывать локальные инструкции при переходе в соответствующий каталог.

## Примеры

### Пример 1. Готовый файл CLAUDE.md для веб-приложения на React / Next.js
```markdown
# Инструкции проекта Web Portal

## Команды разработчика
- `npm run dev` — запуск локального сервера разработки на порту 3000
- `npm run test -- -u` — обновление снэпшотов тестов

## Правила написания кода
- Использовать функциональные компоненты и хуки (без классовых компонентов).
- Стилизовать исключительно через модульные CSS-файлы (*.module.css).
- Для управления состоянием использовать Zustand.
- Запрещено использовать тип `any` в TypeScript.
```

### Пример 2. Готовый файл CLAUDE.md для backend-сервиса на Python / FastAPI
```markdown
# Правила разработки REST API Сервиса

## Основные команды
- `poetry run uvicorn main:app --reload` — запуск сервера
- `poetry run pytest` — выполнение автотестов
- `poetry run black .` — форматирование кода

## Архитектурные правила
- Структура: Router -> Service -> Repository.
- Все модели данных описываем строго через Pydantic v2.
- Документировать все эндпоинты через docstrings на русском языке.
```

## Частые ошибки и вопросы

**Вопрос 1: Не перегрузит ли большой файл CLAUDE.md контекстное окно ИИ?**
*Ответ:* Файл `CLAUDE.md` должен содержать только лаконичные, конкретные правила и команды без длинных рассуждений. Оптимальный объем — от 30 до 100 строк. Избегайте добавления исходного кода файлов в память — для этого у Claude Code есть инструменты чтения файлов.

**Вопрос 2: Чем различаются файл CLAUDE.md и авто-память (/memory)?**
*Ответ:* Файл `CLAUDE.md` создается и редактируется разработчиком вручную и содержит жесткие правила проекта. Авто-память генерируется самим Claude Code в процессе работы, когда он обнаруживает новые паттерны или особенности кода.

**Вопрос 3: Заметит ли Claude Code изменения в CLAUDE.md во время активной сессии?**
*Ответ:* Если вы откорректировали `CLAUDE.md` прямо во время сессии, рекомендуется перезапустить диалог или отправить команду сброса контекста, чтобы инструмент перечитал файл инструкций заново.

**Вопрос 4: Можно ли добавлять CLAUDE.md в репозиторий Git?**
*Ответ:* Да, файл `CLAUDE.md` рекомендуется фиксировать в системе контроля версий Git. Это позволит всем членам вашей команды и ИИ-ассистенту работать по единым правилам.

**Вопрос 5: Что делать, если Claude Code игнорирует одно из правил из CLAUDE.md?**
*Ответ:* Сформулируйте правило более жестко, добавив ключевые слова: "КРИТИЧЕСКИ ВАЖНО" или "КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО". Убедитесь, что в правиле нет двусмысленных формулировок.

## Итог
Настройка памяти в Claude Code через файл `CLAUDE.md` и команду `/memory` экономит до 30% рабочего времени при ежедневной разработке. Вам больше не придется тратить силы на повторяющиеся вводные инструкции в начале каждого диалога. Создайте базовый файл `CLAUDE.md` в вашем текущем проекте по предоставленным шаблонам уже сегодня и оцените новый уровень комфорта при работе с ИИ-ассистентом!
