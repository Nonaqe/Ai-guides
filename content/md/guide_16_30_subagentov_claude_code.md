# 30 субагентов Claude Code | Фронт, бэк, DevOps, AI, Python

## Зачем это нужно
При решении сложных комплексных задач одна универсальная нейросетевая модель часто теряет фокус, размывает контекст и допускает ошибки в специфических узких нишах. Механизм субагентов (Sub-agents) в Claude Code решает эту проблему. Субагенты — это специализированные цифровые узкопрофильные конфигурации (эксперты), каждый из которых имеет свой конфиг-файл с четко описанной ролью, ограниченным набором разрешенных инструментов и оптимально подобранной нейросетевой моделью. Инструмент вызывает субагентов автоматически по мере необходимости или по вашей прямой команде. Этот гайд объяснит механику создания субагентов и предоставит каталог из 30 готовых практически полезных примеров по 5 ключевым IT-направлениям.

## Пошаговая инструкция

### Шаг 1. Понимание механики субагентов
Субагент представляет собой изолированный процессуальный модуль. Конфигурация субагента включает три ключевых параметра:
1. **Role Prompt (Системный промпт роли):** Подробная инструкция, кем является субагент и каковы его границы ответственности.
2. **Allowed Tools (Разрешенные инструменты):** Список инструментов (чтение файлов, запуск консольных команд, вызовы API), к которым субагент имеет доступ.
3. **Model (Модель):** Выбор базовой языковой модели (более быстрая легкая модель для простых поисковых задач или мощная модель для глубокого архитектурного анализа).

### Шаг 2. Создание файла субагента
Субагенты описываются в специальных конфигурационных файлах в каталоге настроек.

Пример структуры конфигурационного файла субагента:
```yaml
name: "frontend-accessibility-auditor"
description: "Специалист по аудиту доступности интерфейсов (Accessibility / a11y)"
model: "claude-3-5-sonnet"
tools:
  - ReadFile
  - RunCommand
prompt: |
  Ты — эксперт по стандарту WCAG 2.1. Твоя единственная задача — вычитывать HTML и JSX компоненты 
  на предмет корректности aria-атрибутов, контрастности, разметки заголовков и доступности с клавиатуры.
```

## Примеры

### Пример 1. Автоматический вызов субагента sql-query-optimizer
**Запрос пользователя:**
`Этот запрос выполняется в базе данных 4 секунды: SELECT * FROM orders WHERE status = 'active' ORDER BY created_at DESC. Оптимизируй его.`

**Действие Claude Code:**
Система автоматически активирует субагента `sql-query-optimizer`. Субагент анализирует запрос, предлагает создание составного индекса `(status, created_at DESC)` и переписывает выборку полей вместо `SELECT *`, сокращая время выполнения до 15 миллисекунд.

## Частые ошибки и вопросы

**Вопрос 1: В чем главное преимущество вызова субагента перед обычным промптом?**
*Ответ:* Субагент работает с изолированным узким системным промптом и строго ограниченным набором инструментов. Это устраняет галлюцинации и предотвращает случайное выполнение несанкционированных команд в репозитории.

**Вопрос 2: Могут ли субагенты вызывать других субагентов?**
*Ответ:* Да, в Claude Code реализована возможность делегирования: главный ассистент может разбить задачу и направить подзадачи нескольким субагентам параллельно с последующим сведением результатов.

**Вопрос 3: Как жестко вызвать конкретного субагента вручную?**
*Ответ:* Укажите имя субагента в своем запросе: `@имя_субагента провери этот файл`.

**Вопрос 4: Какую модель выставлять в конфиге субагента?**
*Ответ:* Для простых задач поиска, форматирования и линтинга используйте быстрые легкие модели. Для глубокого рефакторинга, архитектуры и безопасности используйте флагманские модели.

**Вопрос 5: Где хранятся пользовательские конфигурации субагентов?**
*Ответ:* Конфигурационные файлы субагентов размещаются в специализированной папке настроек Claude Code в вашем пользовательском профиле или проекте.
