# Подключение MCP-серверов к Claude Code: Внешние БД и API

## Зачем это нужно
При решении сложных инженерных задач консольный ИИ-ассистент ограничен файлами локального репозитория. Для выполнения сквозных задач разработчику регулярно требуется подключать ИИ к внешним источникам данных: базам данных PostgreSQL/MySQL, таск-трекерам GitHub/Jira, документации и внешним API-сервисам. Протокол MCP (Model Context Protocol) решает эту проблему. MCP предоставляет открытый стандарт подключения внешних серверов инструментов и контекста к Claude Code. Этот гайд содержит подробное руководство по архитектуре MCP, созданию файла конфигурации `.mcp.json`, подключению готовых MCP-серверов и работе с внешними базами данных напрямую из консоли.

## Что внутри
* Понимание архитектуры Model Context Protocol (MCP): клиент, сервер и инструменты (Tools).
* Пошаговая настройка файла конфигурации `.mcp.json` в корне проекта.
* Подключение MCP-сервера PostgreSQL для выполнения безопасных SQL-запросов.
* Подключение MCP-сервера GitHub для работы с issues и pull-запросами.
* Команда консоли `claude mcp add` для быстрого добавления интеграций.
* Разбор практического примера проведения миграций и сбора метрик из БД.
* Ответы на частые вопросы по безопасности прав доступа и отладке MCP-соединений.

## Пошаговая инструкция

### Шаг 1. Архитектура протокола MCP (Model Context Protocol)
Model Context Protocol построен по клиент-серверной архитектуре:

1. **MCP Client (Клиент):** Консольный инструмент Claude Code, который формирует запросы и передает контекст.
2. **MCP Server (Сервер):** Изолированный процесс (на Node.js или Python), который предоставляет набор вызова инструмента (`tools`), ресурсов (`resources`) или промптов (`prompts`).
3. **Transport (Транспорт):** Связь между клиентом и сервером через стандартные потоки ввода-вывода (`stdio`) или HTTP/SSE.

---

### Шаг 2. Конфигурирование файла `.mcp.json` в проекте
Для постоянного подключения внешних инструментов к проекту создайте файл `.mcp.json` в корневой директории репозитория.

Пример конфигурации `.mcp.json`:
```json
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-postgres",
        "postgresql://user:password@localhost:5432/my_database"
      ]
    },
    "github": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-github"
      ],
      "env": {
        "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_your_personal_access_token_here"
      }
    }
  }
}
```

---

### Шаг 3. Добавление MCP-сервера через CLI-команду
Помимо создания файла `.mcp.json`, подключение сервера можно выполнить прямо из консоли.

1. **Добавление сервера PostgreSQL:**
   `claude mcp add postgres -- npx -y @modelcontextprotocol/server-postgres postgresql://localhost/dev_db`

2. **Проверка списка подключенных MCP-серверов:**
   Внутри сессии Claude Code выполните команду `/mcp` для просмотра активных серверов и доступных инструментов.

---

### Шаг 4. Взаимодействие с внешними системами через Claude Code
После подключения MCP-сервера вы можете давать ИИ-ассистенту задачи на естественном языке, использующие внешние данные.

1. **Запрос к базе данных PostgreSQL:**
   `Прочитай структуру таблицы users из базы данных через MCP. Найди пользователей, зарегистрированных за последние 24 часа без подтвержденного email, и выведи их количество.`

2. **Запрос к GitHub API:**
   `Прочитай список открытых issues в нашем GitHub-репозитории с меткой "bug", найди среди них относящиеся к авторизации и сформируй сводный отчет.`

## Примеры

### Пример 1. Выполнение безопасного аудита структуры базы данных через MCP
**Запрос пользователя:**
`Подключись к подключенной базе данных через MCP-сервер postgres. Проверь таблицу orders на наличие отсутствующих индексов по внешним ключам (foreign keys), которые замедляют выборку.`

**Действие Claude Code:**
ИИ вызывает инструмент `postgres_query`, считывает системный каталог `pg_stat_user_tables`, находит отсутствующий индекс на столбце `customer_id` и генерирует SQL-скрипт миграции.

---

### Пример 2. Автоматическое создание pull-запроса в GitHub через MCP
**Запрос пользователя:**
`Создай новую ветку git "fix/auth-leak", внеси изменения в auth.js и отправь pull request в наш GitHub-репозиторий с описанием внесенных правок.`

**Результат:** Claude Code автоматически использует инструмент MCP-сервера GitHub для создания pull request с готовым описанием изменений без необходимости переходить в веб-интерфейс GitHub.

## Частые ошибки и вопросы

**Вопрос 1: Безопасно ли передавать пароль от базы данных в файл `.mcp.json`?**
*Ответ:* Не храните пароли в открытом виде в файле `.mcp.json`, если репозиторий публичный. Используйте переменные окружения (`env`) и передавайте пароли через файл `.env`, добавленный в `.gitignore`.

**Вопрос 2: Что делать, если MCP-сервер не запускается или выдает ошибку `spawn ENOENT`?**
*Ответ:* Убедитесь, что у вас установлена среда Node.js версии 22+ (проверьте командой `node -v`) и что команду `npx` можно выполнить из командной строки PowerShell / Terminal.

**Вопрос 3: Могу ли я написать собственный MCP-сервер на Python или TypeScript?**
*Ответ:* Да, стандарт MCP является открытым. Вы можете написать свой сервер с помощью официального SDK (на TypeScript или Python), описав собственные функции и инструменты.

**Вопрос 4: Чем MCP отличатся от обычного запуска скриптов через консоль?**
*Ответ:* MCP предоставляет строгую спецификацию типов, аргументов и описаний функций, благодаря чему ИИ точно знает, какие параметры нужно передать и каков формат возвращаемого ответа.

**Вопрос 5: Сколько MCP-серверов можно подключить одновременно?**
*Ответ:* Лимита нет, однако рекомендуется подключать только актуальные для текущего проекта сервера, чтобы не перегружать контекст модели лишними инструментами.
