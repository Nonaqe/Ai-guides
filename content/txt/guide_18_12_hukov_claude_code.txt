# 12 хуков Claude Code | Автотест, деплой, напоминания

## Зачем это нужно
Автоматизация разработки становится действительно безупречной тогда, когда рутинные проверки, прогон тестов, отправка уведомлений и сборка деплоя происходят автоматически при наступлении определенных событий. В Claude Code для этого предусмотрен механизм хуков (Hooks) — специальных скриптов, которые автоматически срабатывают в ответ на события жизненного цикла диалоговой сессии. Настройка хуков позволяет предотвратить коммит поломанного кода, автоматически проверять синтаксис при изменении файлов и отправлять результаты сборки в таск-трекеры. Этот гайд объяснит устройство хуков и предоставит 12 готовых практических примеров для автоматизации автотестов, деплоя и уведомлений.

## Что внутри
* Механика работы хуков и жизненный цикл событий сессии Claude Code.
* Официальный список событий жизненного цикла: только реальные события.
* Инструкция по созданию и регистрации файлов хуков.
* Блок 1: 4 хука для автоматического запуска автотестов и проверки качества.
* Блок 2: 4 хука для автоматизации процессов деплоя и сборки.
* Блок 3: 4 хука для отправки уведомлений, напоминаний и аудита.
* Ответы на частые вопросы по отладке и безопасности хуков.

## Пошаговая инструкция

### Шаг 1. Понимание архитектуры и событий жизненного цикла
Хук — это исполняемый скрипт (Bash, Python или Node.js), привязанный к конкретному системному событию Claude Code.

Официальные события жизненного цикла (используются строго данные имена):
* **SessionStart** — Срабатывает в момент запуска рабочей сессии.
* **UserPromptSubmit** — Срабатывает при отправке пользователем нового промпта до его обработки.
* **PreToolUse** — Срабатывает непосредственно перед вызовом любого инструмента (например, запись файла).
* **PostToolUse** — Срабатывает сразу после успешного выполнения инструмента.
* **PostToolUseFailure** — Срабатывает при ошибке выполнения инструмента.
* **Notification** — Срабатывает при формировании системного уведомления.
* **SubagentStart** — Срабатывает в момент запуска субагента.
* **SubagentStop** — Срабатывает при завершении работы субагента.
* **PreCompact** — Срабатывает перед выполнением сжатия контекста.
* **PostCompact** — Срабатывает после завершения сжатия контекста.
* **Stop** — Срабатывает при остановке генерации или отмене действия.
* **SessionEnd** — Срабатывает при закрытии сессии.

### Шаг 2. Структура и регистрация хука
Хуки настраиваются в файле конфигурации или регистрируются в директории настроек.

Пример конфигурации хука в JSON:
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "command": "bash .claude/hooks/run_linter.sh"
      }
    ]
  }
}
```

### Шаг 3. 12 Практических примеров хуков

#### Блок 1: Автотесты и контроль качества кода
1. **Хук "Авто-линтер при редактировании" (`PostToolUse`):**
   Автоматически запускает `eslint` или `ruff` каждый раз, когда Claude Code изменяет любой файл в проекте.
2. **Хук "Прогон упавших тестов" (`PostToolUseFailure`):**
   При ошибке модификации файла с тестами автоматически запускает модульный тест и передает лог ошибки обратно ассистенту.
3. **Хук "Проверка секретов в коде" (`UserPromptSubmit`):**
   Сканирует отправляемый текст и редактируемый файл на случайную утечку API-ключей до передачи нейросети.
4. **Хук "Итоговый прогон тест-сюита" (`PreCompact`):**
   Запускает полное регрессионное тестирование перед сжатием контекста.

#### Блок 2: Деплой и сборка приложения
5. **Хук "Проверка сборки бандла" (`PostToolUse`):**
   Выполняет тестовую сборку проекта `npm run build` после завершения редактирования ключевых компонентов.
6. **Хук "Авто-коммит при завершении" (`SessionEnd`):**
   Сохраняет текущие изменения в изолированную ветку Git при выходе из сессии.
7. **Хук "Уведомление о стажировке деплоя" (`SubagentStop`):**
   Отправляет статус завершения работы деплой-субагента в консоль.
8. **Хук "Очистка временных артефактов" (`SessionStart`):**
   Удаляет кэш-файлы и временные бинарники при старте новой сессии.

#### Блок 3: Уведомления, напоминания и аудит
9. **Хук "Звуковое оповещение о завершении задачи" (`Notification`):**
   Воспроизводит системный звук при готовности ответа ИИ.
10. **Хук "Логирование затрат сессии" (`SessionEnd`):**
    Записывает итоговое количество израсходованных токенов в файл отчета `logs/costs.log`.
11. **Хук "Напоминание об обновлении документации" (`Stop`):**
    Выводит напоминание разработчику об обновлении файла `CHANGELOG.md` при ручной остановке процесса.
12. **Хук "Приветственный аудит репозитория" (`SessionStart`):**
    Выводит текущий статус веток Git и не закоммиченных файлов при старте работы.

## Примеры

### Пример реализации хука "Авто-линтер при редактировании"
**Событие:** `PostToolUse`

**Код скрипта (`run_linter.sh`):**
```bash
#!/bin/bash
# Проверяем, был ли изменен JS/TS файл
if [[ "$CLAUDE_FILE_TARGET" =~ \.(js|ts|tsx)$ ]]; then
  echo "Запуск авто-исправления линтером..."
  npx eslint --fix "$CLAUDE_FILE_TARGET"
fi
```

**Результат:** Любые правки, внесенные нейросетью, моментально приводятся к единому корпоративному стилю кода без лишних запросов.

## Частые ошибки и вопросы

**Вопрос 1: Что произойдет, если скрипт хука завершится с ошибкой (код возврата не 0)?**
*Ответ:* Если хук привязан к событию пре-обработки (например, `PreToolUse`), его ошибка заблокирует выполнение инструмента и передаст причину сбоя ассистенту для исправления.

**Вопрос 2: Могут ли хуки замедлить работу Claude Code?**
*Ответ:* Если вы повесите тяжелый интеграционный тест на событие `PostToolUse`, он будет запускаться при каждом изменении любого файла. Назначайте тяжелые тесты на события `SessionEnd` или `PreCompact`.

**Вопрос 3: Можно ли писать хуки на языке Python вместо Bash?**
*Ответ:* Да, вы можете запускать любой интерпретатор: `python3 .claude/hooks/my_hook.py`.

**Вопрос 4: Как временно отключить выполнение хуков?**
*Ответ:* Вы можете запустить Claude Code с флагом отключения хуков или закомментировать конфигурацию в файле настроек.

**Вопрос 5: Доступны ли переменные окружения внутри скрипта хука?**
*Ответ:* Да, Claude Code передает в окружение хука контекстные переменные: путь к редактируемому файлу, имя события, статус выполнения и имя субагента.
