# Claude Code под тебя за 5 минут | 6 готовых CLAUDE.md

## Зачем это нужно
Настройка файла памяти `CLAUDE.md` — это первый и самый важный шаг для превращения Claude Code в эффективного разработчика, понимающего правила именно вашей команды. Однако составление такого файла с нуля требует времени и знания оптимальной структуры. Этот гайд решает проблему быстрой настройки: вы получите 6 готовых, выверенных шаблонов `CLAUDE.md` под основные типы проектов (Frontend, Backend, Python-скрипты, Монорепозитории, Документация и Data Science). Вам останется только скопировать нужный блок в корень своего репозитория и запустить работу.

## Что внутри
* Пошаговая инструкция по быстрой интеграции шаблона `CLAUDE.md` за 5 минут.
* Шаблон 1: Web Frontend (React / Vue / Next.js / TypeScript).
* Шаблон 2: Backend API (Node.js / Express / NestJS).
* Шаблон 3: Python Сервисы и Автоматизация (FastAPI / Django / Poetry).
* Шаблон 4: Скрипты и Утилиты (Bash / Python / Automation).
* Шаблон 5: Техническая Документация и База Знаний (Markdown / Astro / Docusaurus).
* Шаблон 6: Data Science и Аналитика (Jupyter / Pandas / Scikit-Learn).

## Пошаговая инструкция

### Шаг 1. Проверка установки Claude Code
Перед скопированием шаблона убедитесь в доступности консольной утилиты.

1. **Команда установки для Windows PowerShell:**
   `irm https://claude.ai/install.ps1 | iex`
2. **Команда установки через npm (Node.js 22+):**
   `npm install -g @anthropic-ai/claude-code`
3. **Проверка версии:**
   `claude --version`

### Шаг 2. Размещение файла в проекте
1. Перейдите в корневую папку вашего рабочего проекта.
2. Создайте файл с точным именем `CLAUDE.md`.
3. Выберите из списка ниже шаблон, подходящий под ваш стек технологий, скопируйте его содержимое и сохраните файл.

---

### Шаг 3. 6 Готовых шаблонов CLAUDE.md

#### Шаблон 1. Web Frontend (React / TypeScript / Next.js)
```markdown
# Frontend Инструкции

## Команды
- Запуск dev-сервера: `npm run dev`
- Тесты: `npm run test`
- Линтер: `npm run lint`
- Сборка: `npm run build`

## Правила написания кода
- Писать только на TypeScript с явным указанием типов (без `any`).
- Использовать функциональные компоненты и стрелочные функции.
- Именовать компоненты в PascalCase, хуки — с префикса `use`.
- Стилизация: TailwindCSS или CSS Modules.
```

#### Шаблон 2. Backend API (Node.js / Express / TypeScript)
```markdown
# Backend API Инструкции

## Команды
- Разработка: `npm run start:dev`
- Миграции БД: `npx prisma migrate dev`
- Запуск тестов: `npm run test:e2e`

## Архитектура и стиль
- Модульная архитектура: Controller -> Service -> Repository.
- Ошибки обрабатывать через единый Middleware с кодами HTTP status.
- Логирование всех ошибок через Winston/Pino.
- Все эндпоинты покрывать валидацией входных схем Zod.
```

#### Шаблон 3. Python Сервисы (FastAPI / Poetry)
```markdown
# Python FastAPI Сервис

## Команды
- Запуск сервера: `poetry run uvicorn main:app --reload`
- Автотесты: `poetry run pytest -v`
- Форматирование: `poetry run ruff check . --fix`

## Стандарты кода
- Версия Python 3.11+.
- Строгая типизация параметров вызовов и функций (Type Hints).
- Модели данных описывать через Pydantic v2.
- Асинхронные обработчики с асинхронными вызовами БД (SQLAlchemy async).
```

#### Шаблон 4. Скрипты и системная автоматизация (Python / Bash)
```markdown
# Скрипты и Автоматизация

## Команды
- Проверка скриптов: `bash -n script.sh`
- Запуск Python скриптов: `python main.py`

## Правила
- Скрипты должны быть кроссплатформенными (Windows / Linux).
- Обязательная проверка кода возврата (exit code) каждой внешнего утилиты.
- Наличие флага `--help` с описанием всех аргументов командной строки.
- Логировать прогресс выполнения в `stdout` с метками времени.
```

#### Шаблон 5. Техническая Документация (Markdown / Docusaurus)
```markdown
# Документация Проекта

## Команды
- Локальный просмотр: `npm run start`
- Сборка сайта: `npm run build`

## Правила оформления
- Формат файлов — строго Markdown (GFM).
- Использовать понятную заголовную иерархию (один H1 на файл).
- Ссылки на код делать через relative paths.
- Добавлять схемы в формате Mermaid для визуализации процессов.
```

#### Шаблон 6. Data Science и Машинное обучение
```markdown
# Data Science & ML Проект

## Команды
- Запуск Jupyter: `jupyter lab`
- Запуск обучения: `python train.py`

## Правила
- Обязательный фиксированный `random_seed = 42` для воспроизводимости.
- Разделение кода: датасеты в `data/`, модели в `models/`, скрипты в `src/`.
- Не сохранять бинарные файлы моделей в Git репозиторий.
```

После создания файла `CLAUDE.md` запустите диалог в терминале:
`claude`

Отправьте короткий запрос:
`Создай новый эндпоинт авторизации пользователя.`

**Результат:** Claude Code автоматически прочитает файл `CLAUDE.md`, определит ваш стек (например, FastAPI + Pydantic v2), напишет асинхронную функцию с полной типизацией и обработкой ошибок строго по вашему стандарту без дополнительных вопросов.

## Частые ошибки и вопросы

**Вопрос 1: Можно ли комбинировать правила из разных шаблонов в одном CLAUDE.md?**
*Ответ:* Да! Вы можете свободно объединять блоки (например, взять команды сборки из шаблона Frontend и правила стиля из шаблона Python, если делаете фулстек-проект).

**Вопрос 2: Где в репозитории должен лежать файл CLAUDE.md?**
*Ответ:* Файл должен лежать строго в корневой директории вашего проекта (рядом с `.git`, `package.json` или `pyproject.toml`).

**Вопрос 3: Как проверить, что Claude Code действительно применил правила из шаблона?**
*Ответ:* При старте сессии Claude Code выводит служебное сообщение о загруженных файлах конфигурации. Также вы можете спросить напрямую: `"Каким правилам стиля кода ты следуешь в этом проекте?"`.

**Вопрос 4: Стоит ли вносить в шаблон личные токены или API-ключи?**
*Ответ:* Категорически нет! Никогда не храните пароли, секретные ключи и токены в файле `CLAUDE.md`. Используйте для этого переменные окружения и файл `.env`.

**Вопрос 5: Сколько времени занимает адаптация готового шаблона под проект?**
*Ответ:* Обычно от 2 до 5 минут: скопировать текст, исправить названия команд под ваш `package.json` или `Makefile` и сохранить файл.
